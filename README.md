# Low Supply

A child with type 1 diabetes taps a supply that is running low. Both parents get a
notification. Either parent marks it ordered, and the child hears back.

One web app with two faces, the parent app and the child app, picked when a device links.
It installs to a phone's Home Screen. Built for one family's own use. It is not
distributed or sold.

For a tour with screenshots, see [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md). The rules the
app is built to, and where its design system lives, are in
[SITE-CONTEXT.md](SITE-CONTEXT.md). Read that before changing a screen or its words.

## What it does

- **A child asks.** One large button for each supply, then Running low or I am out. A
  second tap updates the same request. The child can cancel.
- **Both parents hear it.** Requests sit on one list they share. If nobody acts, the
  reminder repeats at a pace the parents choose.
- **A parent marks it ordered.** The child gets a note, and the supply's button turns
  green for five days.
- **Or ordered, but not ready until a date.** For a pharmacy or insurance delay. The child
  sees a countdown in days instead of the date, and both parents get a follow up reminder
  on the day.
- **Check ins.** On a schedule the parent sets, the app asks the child whether anything is
  running low. Quiet hours cover school and sleep.
- **Quick info.** A parents only page of links and office numbers: the patient portal, the
  pharmacy, the doctor's office. A phone number can carry a menu choice to dial.
- **No accounts and no real names.** People are nicknames. A device joins with a code that
  works once, for one person, for 30 minutes.
- **Reset.** Any device can unlink itself. A parent can delete the family and start over.

It only passes messages about supplies. It never reads glucose and never suggests a dose.

## Run it on this Mac

    npm install
    npm run dev

Then open http://localhost:4350. The first run makes notification keys and keeps them in
`.env.local`, which git ignores. Families are saved as JSON files in `data/`.

To try all three roles on one Mac, use three browser profiles or private windows: one
sets up the family, the others link with the codes it shows.

## Checks

    npm test            the rules, with a fake clock and fake notifications
    npm run e2e         two parents and a child in a real browser (the dev server must be running)
    npm run qa          every screen in every state, against WCAG 2.2 AA (starts its own server)
    npm run check:copy  the never-say list
    npm run demo        remakes the walkthrough screenshots and the demo video

`npm run qa` covers what the flow test cannot reach by tapping: a late order, a child
with every supply on, a form error, a failed send. On each it runs axe, sideways scroll,
text spilling or breaking mid word, target size, wider text spacing, keyboard reach, a
visible focus ring that is not covered, edge contrast, and Windows High Contrast. Run it a
second time in Safari's engine, which has caught things Chromium did not:

    QA_BROWSER=webkit npm run qa

A clean run is not proof. It cannot listen to a screen reader or judge a layout, so a
real iPhone and a person still have to look.

`e2e`, `qa` and `demo` borrow Playwright and axe from `~/portfolio-astro`. `demo` also
needs ffmpeg.

## How it is put together

- `public/` is the whole app: plain HTML, CSS and JavaScript modules, no build step.
  `js/parent.js` and `js/child.js` are the two faces, `js/start.js` is install and linking,
  and `js/app.js` draws screens and runs actions.
- `lib/core.js` holds every rule and touches no storage or network. `lib/http.js` is the
  backend around it. `lib/store.js` saves to a folder here, or to Vercel Blob when deployed.
- `server.mjs` runs it locally. `api/[route].js` is the same backend as one hosted function.
- `public/sdc.css` is the Steven Design Co. system, generated by `npm run sync:sdc`. The
  app's own parts are in `public/app.css`, named `ls-*`, and read only from system tokens.
- A linked device holds a random token. The server keeps only a hash of it.
- A form that fails keeps what was typed and shows the reason under the field it is about.

## Where it is live

https://family.stevendesignco.com/low-supply, inside the family site, since November 11,
2026. The family site is built and deployed from `~/Documents/claude/LLC/LLC/private-sites`.

To ship a change:

1. Run the checks above.
2. `npm run sync:family` copies the app into the family site folder. Never edit those
   copies by hand.
3. From `private-sites/family/site`, run the Vercel production deploy. That is Steve's
   call each time.

Settings on the host, by name only. The values live in Vercel and Steve's password
manager, never in a file here.

- `LOW_SUPPLY_VAPID_PUBLIC_KEY` and `LOW_SUPPLY_VAPID_PRIVATE_KEY`: the notification keys.
  Set since November 12, 2026.
- `BLOB_READ_WRITE_TOKEN`: the family site's private Blob store, where families are saved.
- `CRON_SECRET`: lets the daily timer call `/api/low-supply/tick`. Not set yet.
- `LOW_SUPPLY_SETUP_CODE`: optional. When set, starting a new family asks for it. Not set,
  so anyone who reaches the address can start a family of their own. Families cannot see
  each other.

The clock: reminders, follow ups and check in nudges fire when any family device opens
the app. A daily timer at 14:00 UTC is configured as a backstop, and needs `CRON_SECRET`
to be allowed in.

## Known limits

- iPhone notifications only work after Add to Home Screen. The app walks through it.
  Delivery to a real iPhone has not been confirmed yet.
- The link code is meant to ride along into the Home Screen app by itself. That step is
  not proven on a real iPhone. Typing the code always works.
- iPhones will not speak until the first tap after opening, so a check in question may be
  silent until the child touches the screen.
- A Quick info link opens whatever the phone decides: the site, or its app if installed.
  The app cannot force another app open. The menu choice is dialed after a fixed two
  second pause, which may be early for some phone menus.
- A supply the plan has stopped filling has no option of its own yet.
- Type sizes are fixed pixels. They follow page zoom but not a phone's larger text setting.
- No screen reader has been run against it by a person.
- The app icon is a placeholder.
