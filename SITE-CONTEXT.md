# Site context: Low Supply

A family app. A child with type 1 diabetes taps a supply, both parents get told, and one
of them marks it ordered. First working version built 2026-11-11 from Steve's build brief.
Personal family use only. Not distributed, not sold.

## How it ships
- Runs on this Mac with `npm run dev` at http://localhost:4350.
- Live for the family at https://family.stevendesignco.com/low-supply. `npm run sync:family`
  copies the app into the family site folder, and the Vercel deploy from there puts it
  live. Deploying is Steve's call.
- Settings (notification keys, the optional setup code) live in the host's settings and
  Steve's password manager, never in a file here.

## Where the design system lives
- **Tokens and controls:** `public/sdc.css`, generated by `npm run sync:sdc` from
  `~/portfolio-astro/storybook/src/sdc.css` (the CSS stevendesignco.com ships). Never
  edited by hand. Run the sync again after an SDC release.
- **App parts:** `public/app.css`, named `ls-*`. Every value reads from an SDC token.
- **Icons:** Tabler Icons (MIT), copied by `npm run sync:icons` into `public/js/icons.js`.
  The supply to icon map is `public/js/catalog.js`. A custom icon set replaces these later.
- **Light theme only**, like the other family apps. Display face is Nickel Gothic from
  Typekit kit uic8bwd, body is Inter served from `public/fonts`.

## New parts made for this app (candidates to promote into SDC)
Built on SDC tokens because the system had nothing for them. None are in the system or
its Storybook yet.
- **Tile** (`ls-tile`, `ls-grid`): a full screen grid of large buttons, icon over label.
- **Alert button** (`ls-alert`): the Running low and I am out buttons, with a sent state.
- **Level** (`ls-level`): the small Running low or I am out badge. SDC has no badge.
- **Notice** (`ls-notice`): a message on a status tint, three tones plus plain.
- **Panel** (`ls-panel`) and **List** (`ls-list`): a flat surface card and rows inside it.
- **Dialog** (`ls-dialog`): a short yes or no. SDC's modal is the case study modal.
- **Bar and nav** (`ls-bar`, `ls-nav`): the parent app header.
- **Wait** (`ls-wait`, `ls-moons`): the child's "ordered, but not ready yet" card: one
  moon for each night left (up to ten) and the count as a large number. Added 2026-11-16.
  Tile, Request and Notice each gained a `--wait` variant on the accent color.
- Token gap: SDC has no semantic name for a warning fill. The app aliases
  `--ls-low-fill` to the primitive `--sdc-signal-amber`. A `--sdc-warning-fill` would fix it.
- Token gap: type sizes are px, so they follow page zoom but not a browser's own
  default font size setting.

## Writing
Plain language, Steve's rules: no em dashes, no AI filler, American spelling. The child
side uses as few words as possible, and every word a child sees can be spoken aloud.

## Settled content rules
- **No brand names and no brand images.** Supplies are generic: Sensor, Pump / Pod,
  Insulin, Insulin pen, Pen needles, Glucose meter, Test strips, Ketone test strips, Glucagon,
  Nasal glucagon (the last three added 2026-11-11). Settled in the brief, 2026-11-11.
- **No real names or personal details.** People are nicknames only. No accounts, no email.
  Settled in the brief, 2026-11-11.
- **The app never reads glucose and never suggests a dose.** It only passes a message.
  That is what keeps it out of medical device territory. Settled in the brief, 2026-11-11.
- **Never tell a child something was sent when it was not.** No offline queue. A failed
  send says so on screen and out loud. Claude's call during the build, 2026-11-11.
- **The child sees a countdown, not the date.** A parent types the date; the child sees
  sleeps left, dropping by one each day. Steve's call after testing, 2026-11-16.
- **A ready date is never a promise.** When an order is delayed, the child is told it
  "should be ready" when the count reaches today. Once the day passes, the child sees
  that a parent is checking on it, never a new guess. Claude's call, 2026-11-16.
- **"Ready" is all the app claims.** Closing a delayed order tells the child it is ready,
  not that it is in the house: it may still be at the pharmacy. Claude's call, 2026-11-16.
- **No accessibility overlay widget.** Settled in the brief, 2026-11-11.

## Before anything ships
1. `npm test` (the rules: requests, reminders, check ins, quiet hours, linking).
2. `npm run e2e` with the dev server running (three devices in a real browser, axe on
   every screen at WCAG 2.2 AA, target sizes, sideways scroll at 320px).
3. `npm run check:copy` (the never-say list, read from the app's JavaScript).
4. A look on a real iPhone from the Home Screen. Notifications cannot be proven any other way.

## If it is ever shared outside the family
Not a lawyer. Confirm the medical device question before release, and read up on COPPA
(children under 13) and the FTC health data rules. These are in the brief as later notes.
